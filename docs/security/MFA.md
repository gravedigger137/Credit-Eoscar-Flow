# Multi-Factor Authentication

## Overview

Credit-Eoscar includes TOTP-compatible MFA readiness for staff and administrator accounts.

## Purpose

Protect administrator-only workflows without claiming an external MFA provider is deployed.

## Architecture

- TOTP secrets are generated by `server/mfa-service.ts`.
- Recovery codes are generated once and stored as bcrypt hashes.
- User MFA metadata is stored on the `users` table.
- `MFA_ENFORCE_ADMIN=true` makes admin routes require MFA verification when the admin has MFA enabled.
- MFA setup and verification endpoints are session-authenticated.

## Dependencies

- Authenticator app compatible with TOTP.
- Applied migration `0003_security_hardening`.
- Stable `SESSION_SECRET`.
- `MFA_ENFORCE_ADMIN=true` for production enforcement.

## Folder Structure

- `server/mfa-service.ts`
- `server/auth.ts`
- `server/authorization.ts`
- `db/migrations/0003_security_hardening.sql`

## Security

Endpoints:

- `POST /api/v1/auth/mfa/setup`
- `POST /api/v1/auth/mfa/enable`
- `POST /api/v1/auth/mfa/verify`

Recovery codes are returned once during setup. Operators must store them offline. Admin MFA should be enabled and smoke-tested before real users.

## Maintenance

- Rotate recovery codes after suspected exposure.
- Require MFA for every administrator before production.
- Document account recovery approvals.
